# 주간 재고 리포트 자동화

> **재고 스냅샷 파일 하나를 넣으면, 지표 계산부터 이메일 확정본까지 흐르고
> 사람은 네 번만 개입한다.**

데이터기반의사결정 7기 6주차 산출물 — **트랙 B(본인 데이터)**.
제조업 주간 재고 보고를 대상으로 했다.

🔒 **모든 데이터는 합성이다.** 실제 수치·거래처·인명은 들어 있지 않다.
구조와 제약만 실무에서 복제했다.

## 화면에서 바로 보기

사이드바 **기존 실행 불러오기** → **`run_20260822_1707`**

발송 확정까지 마친 실행이라 **1~8단계 전 과정과 리포트·이메일 확정본**을 그대로 볼 수 있다.

| 단계 | 무엇을 하나 | 주체 |
|---|---|---|
| 1 | 재고 스냅샷 CSV 투입 | **사용자** |
| 2 | 스키마 판정 → 지표 27종 계산 | 시스템 |
| — | **게이트 1** 판정 확정 | **사용자** |
| 3 | 검증 10종 | 시스템 |
| 4 | 대시보드(차트 4종) | 시스템 |
| 5 | 내용 확인 | **사용자** |
| — | **게이트 2** 확인 기록 | **사용자** |
| 6 | 리포트 8장 (2·5·6장은 사람이 작성) | 시스템 |
| 7 | 이메일 초안 | 시스템 |
| — | **게이트 3** 발송 확정 | **사용자** |

게이트 1·2는 되돌릴 수 있지만 **게이트 3은 되돌릴 수 없다.**
잘못했으면 새 실행을 만들고 **이전 확정 기록은 남긴다.**

## 터미널에서 (자동화 스크립트)

```bash
py -X utf8 run_pipeline.py --file _data/stock_snapshot_2026-08-18.csv --month 2026-08-18 --approve-extension
```

1~7단계까지 돈다. **8단계(발송 확정)는 화면에서만** 한다 —
자동화가 편의를 위해 안전장치를 지우면 자동화가 아니라 방치가 된다.

exit code: 정상 `0` · 검증 차단 `1` · 오류 `2`

| 인자 | 뜻 |
|---|---|
| `--file` | 필수. 업로드할 CSV |
| `--month` | 대상 기간. 주간은 `2026-08-18` 형태 |
| `--approve-extension` | 유효구간 확장 승인. **없으면 확장이 필요할 때 중단** |

CLI가 만든 실행은 사이드바에서 이어받는다. 게이트 2·3은 **CLI가 대신하지 않는다.**

## 이 앱이 답하는 것

주간 재고 보고가 오래 답하지 못하던 질문들이다.

| 질문 | 답하는 지표 |
|---|---|
| 안 나가는 재고가 어디 있나 | 무출하 재고금액 |
| **어느 공정에서 막혔나** | **공정별 계획 달성률 · 공정 간 격차** |
| 약속 대비 어디까지 왔나 | 수주 진행률 · 납기 초과 도번 수 |
| 취소된 수주의 재고가 남았나 | 취소 수주 관련 재고금액 |
| 주문보다 많이 만든 재고가 얼마인가 | 수주 초과 재고금액 · 재고 대 수주잔량 배수 |
| A/S 재고가 실수요 대응인가 | A/S 재고 대 실수요 배수 |

**재고 스냅샷만으로는 절반도 답하지 못한다.** 수주 원장과 공정 작업일보를 조인해야
비로소 *"왜 그런가"*가 나온다.

### 이번 회차에서 나온 것

재고가 3.3% 줄었는데 **출하도 함께 줄고 납기 초과가 32% 늘었다.**
공정별로 보니 **도장만 61.7%**(평소 88%)로 무너져 있었고, 사출은 94.5%로 정상이었다.
뒤 공정(레이저·인쇄·검사)이 낮은 것은 **도장에서 받을 물량이 없기 때문**이다.

> ★ **검증 셋 중 둘은 이 병목을 놓쳤다.**
> 전월 대비는 통과(−0.73%)했다 — 병목이 3주째라 전주도 낮았기 때문이다.
> 정상 범위도 간발의 차였다 — 병목 주차가 표본에 들어가 하한을 끌어내렸다.
> **이상이 오래 지속되면 그것이 "정상"이 된다.**
> 그래서 같은 시점의 공정끼리 비교하는 **격차 지표**를 따로 두었다.

## 설계에서 지킨 것

**정의는 코드에 쓰지 않는다.** 지표 30종의 산식·임계값·단위·기대값이 전부
위키 정의서(`.md` 프론트매터)에 있고, 앱은 카탈로그(JSON)를 읽기만 한다.
지표를 고치려면 위키를 고치고 `export_catalog.py`를 다시 돌린다.

**앱은 판단 문장을 쓰지 않는다.** 인과·제안·가치판단·강도·완화 표현 5종을
생성 직후 스스로 검사한다. 2·5·6장(배경·원인·제안)은 비워 두고 사람이 쓴다 —
지우면 받는 사람이 숫자 보고서를 **완결된 분석으로 오해한다.**

**안 한 것을 밝힌다.** 혼입 변수·역인과·가설 검정은 자동화하지 않았고,
그 사실이 리포트 7장 한계 절에 자동으로 실린다.
*"검증 통과"가 실제보다 강한 신뢰를 주지 않게* 하는 장치다.

**계산에 현재 시각을 쓰지 않는다.** 같은 파일 → 같은 결과.
재현성 테스트 4종이 이를 지킨다(`pytest tests/`).

## 구조

```
app.py              8단계 화면 (Streamlit)
run_pipeline.py     CLI — 1~7단계
config.py           ★ 이식할 때 고치는 유일한 파일
catalog/            위키 → JSON 스냅샷 (앱이 읽는 유일한 정의 원천)
pipeline/           profile·calculate·compare·validate·charts·report·pdf_render·email_*
manual/sections.md  사람이 쓰는 2·5·6장 (재생성해도 남는다)
outputs/run_*/      실행 단위 결과 — 이전 것을 덮어쓰지 않는다
```

## 로컬 실행

```bash
py -m pip install -r requirements.txt
py -X utf8 dev_tools/get_fonts.py    # PDF용 한글 폰트 (git 미포함)
py -m streamlit run app.py
```

1~4단계(새 파일 업로드)는 BigQuery 인증이 필요하다 —
`gcloud auth application-default login`.
**5~8단계는 인증 없이도 동작**하므로 배포본에서 기존 실행을 불러볼 수 있다.
